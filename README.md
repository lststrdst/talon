<h1 align="center">Talon</h1>

Плагин для ChatGPT и Codex, который помогает спроектировать интерфейс, разработать функцию, проверить результат и подготовить запуск.

```text
$talon:go Добавь экспорт отчёта в CSV и проверь, что он работает с кириллицей и доступен только нужным ролям.
```

Можно выбрать `@Talon` в чате и описать задачу своими словами. Для явного вызова навыка выбора режима используй `$talon:go`.

## Установка

```sh
codex plugin marketplace add https://github.com/lststrdst/talon.git
codex plugin add talon@talon-marketplace
```

Откройте новый чат Codex в нужном проекте. Для обновления сначала выполните `codex plugin marketplace upgrade talon-marketplace`, затем повторите команду установки плагина.

Для ChatGPT в браузере скачайте [веб-архив Talon 2.15.0](https://github.com/lststrdst/talon/raw/refs/tags/v2.15.0/releases/Talon-2.15.0-web.zip) и выберите «Плагины → Добавить → Загрузить архив плагина». Архив содержит навыки, скрипты и каталог UI/UX Pro Max. Разработчик — `lststrdst`.

Для Hermes Agent, OpenCode, OpenClaw, Pi и DeepSeek Harness скачайте [Talon для агентских рантаймов](https://github.com/lststrdst/talon/raw/refs/tags/v2.15.0/releases/Talon-2.15.0-agents.zip). Скопируйте навыки в `.agents/skills/`. Talon выбирает профиль нужного рантайма по задаче и учитывает способ загрузки навыков, доступные инструменты, разрешения и делегирование. В архиве есть правила для `AGENTS.md`.

Память Talon включена по умолчанию в конкретном проекте. Записи дают следующей сессии рабочие команды и условия, при которых они сработали. Обычный путь — `.agents/talon/learned.md`. Когда `.agents/` защищён песочницей, Talon использует `.talon/learned.md`. Чтобы отключить память, укажите это в задаче или в `AGENTS.md` проекта.

Для обычных задач Talon использует модель основного чата. Для новых обычных подагентов Talon выбирает GPT-6.2 Sol Ultra, для сложного этапа — GPT-6.2 Astra Extra High, если среда поддерживает выбор модели подагента. Повторное поручение сохраняет модель агента. Talon сверяет её перед повторным использованием. В локальном Codex также доступен профиль `talon-astra` из инструкции ниже.

## Режимы

- **Стек проекта** `$talon:stack` — определяет язык, фреймворк, менеджер пакетов и тестовые инструменты по файлам нужного компонента. Build и QA используют этот сценарий, когда стек ещё нужно уточнить.
- **Разработка** `$talon:build` — понять, как устроен код, определить, где добавить функцию, и довести её до проверенного результата. Для PowerShell Talon учитывает скрипты, модули, совместимость версий и запуск на Windows.
- **Сквозная разработка** `$talon:delivery` — продолжить фичу по требованиям проекта, определить область Git diff, выбрать проверки затронутых пакетов и подтвердить совместимость API или готовность к релизу.
- **Дизайн** `$talon:design` — продумать экраны, компоненты, цвета, типографику, адаптивность и доступность через UI/UX Pro Max. Локальный поиск требует Python 3.
- **Изображения** `$talon:visuals` — сгенерировать фото или иллюстрацию, отредактировать исходник, подготовить файлы к публикации и проверить, как они выглядят на странице.
- **Тестирование** `$talon:qa` — проверить то, что уже работает, найти и по запросу исправить баг.
- **Сквозные тесты** `$talon:e2e` — написать и запустить тест пользовательского сценария. Talon использует Maestro на мобильном устройстве или симуляторе, Playwright и Cypress для веба, существующие Appium и Detox по конфигурации проекта. Режим показывает первое упавшее ожидание, команду и артефакт прогона.
- **Воспроизводимые проверки** `$talon:checks` — протестировать сохранность данных при импорте, дубли после потери ответа, клавиатурный фокус и чувствительность тестов к ошибке на границе. Есть исполняемые шаблоны для pytest/Hypothesis, unittest и Playwright, а также сценарии CI и временных БД.
- **Поиск решений** `$talon:research` — найти причину по истории Git, исправления на GitHub и опыт на Reddit, сверить документацию нужной версии. Использует доступный веб-поиск, браузер и при необходимости Agent Reach.
- **Каталоги, политики и Яндекс** `$talon:directory` — выбрать проверку AD DS, LDAP, GPO, DNS и SCIM, разобрать YandexADSCIM, SSO и API Яндекс 360 по официальной документации нужной редакции.
- **Запуск** `$talon:launch` — выбрать аудиторию и канал, подготовить анонс или пилот.
- **Автоматизация** `$talon:workflows` — спроектировать и проверить workflow n8n, тестовый webhook, расписание и обработку повторов. Для выполнения workflow нужен инстанс n8n.
- **Проверка безопасности** `$talon:security` — оценить защиту по коду и конфигурации и составить план исправлений.
- **Подбор навыков** `$talon:autoskills` — автоматически ищет подходящее руководство при конкретном пробеле в разработке, поиске или проверке. Сначала использует доступные навыки. При разрешённом автоматическом подключении готовит один подходящий набор в приватном кэше и применяет его к текущему этапу. Сценарий входит в переносимый архив. Для помощника нужны Node.js 22.6+ и autoskills 0.4.1.

В Build можно попросить написать Python-скрипт и прогнать его на тестовых данных или разобраться со службой на Windows Server, Ubuntu или Debian. Для удалённой работы укажите доступный SSH-алиас или настроенный WinRM. Talon сверит состояние, выполнит запрошенные проверки и покажет наблюдаемый результат. Встроенный `verify.py` проверяет код выхода, ожидаемый вывод и по запросу число прогнанных тестов в свежем JUnit.

Для автоматического подключения достаточно один раз разрешить его в чате или инструкциях проекта. Обычная задача ограничена двумя новыми навыками, а результаты подбора и загрузки используются повторно. Без CLI Talon даёт рекомендацию по файлам проекта. Постоянная установка в проект выполняется по отдельному запросу.

Практики ECC для контрактов, миграций, QA, запуска и управления контекстом входят в основные навыки Talon. Talon открывает руководство по текущему этапу и передаёт дальше критерий приёмки, результат и ссылку на доказательство. Встроенные практики работают без отдельного плагина и хуков. <details>
<summary>Подключить профили QA и Astra</summary>

Восемь QA-профилей покрывают диагностику, браузер, написание E2E-тестов, API, Windows, Linux и SSH, исправление и независимое ревью. Для сложного этапа `talon-astra` закрепляет GPT-6.2 Astra.

```sh
git clone https://github.com/lststrdst/talon.git
cd talon
talon_profiles="$HOME/.codex/agents"
mkdir -p "$talon_profiles"
for profile in plugins/talon/agent-profiles/*.toml; do
  target="$talon_profiles/${profile##*/}"
  if [ ! -e "$target" ] && [ ! -L "$target" ]; then
    cp -n "$profile" "$target"
  fi
done
```

Откройте новый чат. Для установки ролей только в одном проекте скопируйте профили в его `.codex/agents/`. [Документация Codex](https://learn.chatgpt.com/docs/agent-configuration/subagents#custom-agents)

Если `talon-astra` уже установлен, для уровня Extra High обновите в его TOML `model_reasoning_effort` до `"xhigh"`.

<details>
<summary>Дополнительные инструменты</summary>

Устанавливаются отдельно и используются по задаче.

- **OpenAI Plugin Eval** проверяет структуру навыков и манифест плагина Codex. В репозитории Talon можно попросить `$talon:go Оцени этот плагин через Plugin Eval`. [Установка CLI](https://github.com/openai/plugins/blob/main/plugins/plugin-eval/README.md#install-as-a-cli-tool)
- **Vercel Agent Desktop** помогает QA проверить окна, меню и системные диалоги нативного приложения. Если CLI уже установлен, укажите Talon тестовое приложение и нужный сценарий. [Установка и права доступа](https://github.com/vercel-labs/agent-desktop/blob/main/docs/install.md)
- **Graphify** строит карту связей в исходном коде. [Документация](https://docs.graphify.com/open-source/configuration/cli)
- **Agent Reach** помогает найти публичные обсуждения для исследования аудитории. [Репозиторий](https://github.com/Panniantong/Agent-Reach)

</details>
