# Talon · Hermes Agent

## Рабочая среда

1. Сверь активный профиль Hermes, рабочий каталог и среду терминала. Локальный терминал, контейнер и удалённый хост могут видеть разные файлы. Проверь путь к проекту в той среде, где будут выполняться команды, и прочитай действующий `AGENTS.md`.
2. В доверенном Git-проекте Hermes обнаруживает навыки в `.hermes/skills/` и `.agents/skills/`. Проверь `skills_list` или `hermes skills list` в нужном профиле и загрузи точный ID через `skill_view`. Для файловой установки подходит `/harness-hermes`, для активного пакета Talon — `skill_view("talon:harness-hermes")`. Если проектный навык отсутствует, проверь корень, доверие и предупреждения о дубликатах.
3. Сверь доступные наборы инструментов и схему вызова в сессии. Для сервера MCP проверь, что нужный инструмент появился в текущем профиле. Для проверки кода запускай проектный тест из подтверждённой среды терминала и сохраняй команду, код завершения и существенный вывод.

## Когда помогает

- **Независимый разбор.** Если доступен `delegate_task`, передай отдельный исследовательский или ревьюерский вопрос, минимальный контекст, границы доступа и формат результата. Проверь, что в наборе инструментов дочернего агента есть чтение нужного проекта. Следуй схеме текущей сессии для получения результата.
- **Повторяемая работа.** Храни проектные команды и соглашения в `AGENTS.md`, многошаговую процедуру в навыке, а долговременные факты в памяти нужного профиля. При поиске старой проверки используй `session_search`, если он доступен и работа с этой историей входит в задачу.
- **Когда делегирование недоступно.** Выполни разбор или QA в текущей сессии. Для второго профиля подготовь самостоятельное задание с нужным путём и критерием приёмки.

Пример запроса для файловой установки — `/harness-hermes Найди проектный тест для повторного запуска установщика и поручай ревью только при доступном delegate_task`.
