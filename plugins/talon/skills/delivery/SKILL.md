# Talon · Сквозная разработка

Начни с цели пользователя и границ задачи. Фича, воспроизведение сбоя, план и проверка релиза дают разные результаты. Для правки с ясным критерием достаточно ближайшего контракта и целевой проверки.

| Этап | Что открыть |
| --- | --- |
| Понять, что должно измениться, согласовать небольшой шаг или продолжить работу другой сессии | [Требования и передача работы](references/specs.md) |
| Найти затронутые файлы и отнести их к рабочему дереву или ветке | [Область изменений Git](references/change-scope.md) |
| Выбрать тесты затронутых пакетов и подтвердить результат CI на нужной ревизии | [Проверки затронутых компонентов и CI](references/affected-ci.md) |
| Сохранить совместимость API и согласовать выпуск | [Совместимость и релиз](references/compatibility-release.md) |

Для реализации выбери один шаг, который можно проверить через обычную точку входа. Свяжи критерии с подходящими наблюдениями, назначь границы записи отдельным исполнителям при необходимости. Если проект использует свои артефакты требований, продолжай по ним. После изменения обнови область diff и выбери проверки по реальным путям вызовов, контрактам и рискам, которые затронуты.

По манифестам сверяй среду через [Стек проекта](../stack/SKILL.md). Для доказательств прогона используй [Воспроизводимые проверки](../checks/SKILL.md). Перед итогом сравни критерии с фактической ревизией, тестами и проверкой выпуска. Отметь, какие выводы относятся к локальному прогону, CI или работе целевой среды. Для незавершённого шага укажи конкретное условие продолжения.
