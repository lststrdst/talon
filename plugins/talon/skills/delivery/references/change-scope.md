# Область изменений Git

Для ревью, многофайловой правки и отчёта по ветке сначала установи нужный checkout и границу задачи. Зафиксируй исходное состояние до реализации и повтори проверку на итоговом diff. Для одной заранее известной правки достаточно её файла и ближайшего контракта.

Используй [change-scope.py](../scripts/change-scope.py) на Python 3.9+ и Git. Укажи абсолютную папку навыка в `talon_delivery_dir`, рабочий checkout в `talon_project`. Команда возвращает JSON и оставляет проект доступным только для чтения.

```sh
python3 "$talon_delivery_dir/scripts/change-scope.py" --project "$talon_project"
```

Для ревью ветки добавь `--base "$talon_base"`, где `talon_base` — согласованный локально доступный ref или SHA. Тогда будут видны изменения от общего предка до `HEAD` и текущие локальные правки. При недоступной базе проверь доступные refs и явно укажи границу сравнения.

Смотри отдельно `staged`, `unstaged`, `untracked`, `committed` и `conflicts`. Для переименования проверяй обе стороны, поскольку они могут принадлежать разным пакетам. Сохраняй присутствующие изменения пользователя при определении собственных правок. `path_count` показывает полный объём найденных путей. При `truncated` можно уточнить область команды или изменить `--limit`. При конфликтах сначала уточни, какой результат нужен от просмотра неполного состояния.

Если `external_filters_disabled` имеет значение `true`, Git сравнил рабочее дерево без запуска внешних фильтров. Подтверди неоднозначные изменения штатным способом для этого проекта. Вложенный репозиторий проверяй по его собственному корню, если задача включает его рабочее дерево.

Список изменённых путей задаёт область поиска. От каждого значимого изменения проверь вызывающие компоненты, миграции, настройки сборки и сценарии интеграции. Для сложных связей используй Graphify или поиск по исходникам, для известного графа пакетов используй штатный affected runner. Проверяй выбранные команды через файлы и CI проекта.
