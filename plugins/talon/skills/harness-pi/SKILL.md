# Talon · Pi Coding Agent

## Рабочая среда

1. Сверь рабочую папку, `AGENTS.md` и решение о доверии к проекту. Pi ищет `.agents/skills/` от рабочего каталога до корня репозитория и отдельно поддерживает проектную `.pi/skills/`. Когда инструкция появилась в каталоге, прочитай указанный `SKILL.md` или вызови `/skill:harness-pi`.
2. Проверь инструменты текущей сессии. В стандартном CLI исходный набор включает `read`, `bash`, `edit`, `write`. Настройки, параметры запуска и расширения могут изменить его. Доверие к проекту разрешает загрузку его ресурсов, а доступ к файлам и командам зависит от прав процесса и среды изоляции.
3. Для подключения сервиса в актуальных версиях Pi проверь встроенный MCP или заменяющее его расширение. В стандартном CLI `/mcp` показывает состояние, видимость и источник серверов. Проектная конфигурация по умолчанию находится в `.pi/mcp.json` и загружается в доверенном проекте. Для фактической работы проверь доступность конкретного инструмента.

## Когда помогает

- **Правка и локальная проверка.** Найди точку входа инструментами чтения, внеси целевую правку и прогони проектную команду через разрешённый терминальный инструмент. Для режима чтения выбирай только необходимые инструменты и учитывай, что MCP и расширения имеют собственные настройки доступа.
- **Независимое ревью.** Используй делегирование, только если соответствующее расширение или инструмент доступен в сессии. Передай ему цель, пути и критерии без лишнего контекста. Иначе проверь diff в текущей сессии или подготовь отдельный запрос для уже доступной второй сессии.
- **Расширение возможностей.** Для повторяемой процедуры используй навык. Для нового инструмента или обработчика событий изучи API расширений и фактически загруженные ресурсы Pi. Проверяй это по установленной версии.

Пример запроса — `/skill:harness-pi Проверь команды QA этого репозитория и выясни, доступно ли независимое ревью в текущей сессии`.
