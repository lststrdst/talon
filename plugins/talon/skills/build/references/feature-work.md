# Реализация функции в существующем проекте

Применяй этот сценарий для изучения существующего проекта, планирования функции или изменения кода. Учитывай, какой результат запросил пользователь.

## Найди рабочий путь

Прочитай инструкции проекта, состояние diff и команды запуска. Найди обычную точку входа нужного сценария и похожую работающую реализацию. Проследи путь от действия пользователя или входного события через обработчик и состояние до наблюдаемого результата. Для связей между модулями используй [Graphify](graphify.md), начиная с конкретного символа.

Для запроса «как это работает» объясни этот путь со ссылками на исходники, условиями его запуска и местом, где безопаснее добавить нужное поведение. Отдельно обозначь, какие связи подтверждает код и где результат зависит от среды. Для запроса о плане опиши шаги и их проверки без изменения кода.

Определи критерий приёмки на небольшом реальном примере. Для экспорта это может быть файл с ожидаемыми столбцами и кодировкой, полученный обычным действием пользователя. Если решение зависит от внешнего API, формата данных или среды выполнения, проверь эту предпосылку до зависимой реализации. Выбери безопасные тестовые данные и подходящий стенд.

## Выбери изменение по причине

| Работа | Основание и проверка |
| --- | --- |
| Новая функция | Добавь недостающее поведение через существующие границы и соглашения проекта. Проверь критерий приёмки через нормальную точку входа. |
| Рефакторинг | Назови конкретное затруднение, которое устраняет изменение. Сохрани контракты вызывающего кода, форматы данных и наблюдаемое поведение. |
| Отладка | Получи воспроизводимое отклонение и отличи предполагаемую причину от ближайшей альтернативы наблюдением или проверкой. Исправь подтверждённый путь отказа и повтори исходный сценарий. |

Используй действующие компоненты, методы, модели данных и обработку ошибок. Новая зависимость или абстракция оправдана конкретной потребностью задачи. Учитывай локальные изменения пользователя при выборе файлов и сохраняй их смысл.

## Проведи функцию через состояние и права

Собери сквозной результат, затем проверь затронутые границы. Для изменения данных учитывай существующие записи и переход с предыдущей версии. Для защищённого действия проверь разрешённого пользователя и отказ другому субъекту на границе, где операция выполняется.

Если действие состоит из нескольких записей или обращений к сервисам, определи состояние после частичного отказа и безопасный повтор. Используй принятый в проекте механизм транзакции, идемпотентности или восстановления, когда он требуется сценарием. Для UI согласуй успешное состояние, ожидание и ошибку с фактическим результатом операции. Выбирай проверки по изменению, сохраняя объём поручения.

Для фоновой задачи проследи запуск по расписанию или событию до результата, который можно проверить. Для импорта и экспорта сверь форматы, повторную обработку и частичные данные. Для настройки или флага проверь значение по умолчанию у существующих установок и фактическое переключение поведения.

## Проверь итоговый код

Запусти целевую проверку и обязательные команды проекта из документации, package scripts или CI workflow. При исправлении дефекта сопоставь один и тот же сценарий до и после изменения, если исходное состояние доступно. Используй существующие тесты. Добавляй регрессию, когда существенный риск остаётся непокрытым и его можно надёжно воспроизвести.

Выбери сборку, проверку типов, линтер или интеграционный прогон по затронутому коду и требованиям проекта. Если проверка падает, локализуй причину и укажи, связана ли она с патчем или исходным состоянием среды. После исправления повтори нужный прогон. При новом изменении перепроверь его влияние. Успешный локальный запуск подтверждает выполненную проверку, а статус CI сверяй с фактическим прогоном.

Сверь итоговый diff, критерий приёмки и результаты команд. Для существенного исправления или проверки готовности используй [QA](../../qa/SKILL.md) с точной версией и собранными свидетельствами.

В ответе назови реализованное поведение, причину важных решений, выполненные проверки и конкретные пробелы. Если контекст подсказывает полезное продолжение, предложи один следующий шаг с ожидаемым эффектом после завершения запрошенной работы.
