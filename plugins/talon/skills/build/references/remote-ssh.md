# Работа с сервером по SSH

Используй подтверждённый SSH-алиас или хост из задачи и штатный доступ проекта. Уточни, на каком компьютере работает агент: локальный `ssh`, VPN, bastion и ключи рабочего Mac могут быть недоступны веб-сессии. Проверь путь подключения локально через `ssh -G <alias>` и используй только сведения о целевом хосте, пользователе и порте. Проверенный ключ хоста должен быть известен клиенту; при отсутствии или изменении ключа подтверди его через доверенный канал администратора.

Для машинного запуска на Linux-хосте пример только на чтение:

```sh
ssh -T -o BatchMode=yes -o StrictHostKeyChecking=yes -o ForwardAgent=no \
  -o ConnectTimeout=10 -o ServerAliveInterval=10 -o ServerAliveCountMax=2 \
  ops-pilot 'hostname; id -un; cat /etc/os-release'
```

`ops-pilot` обозначает заранее настроенный алиас со штатной учётной записью проекта. `BatchMode` выключает интерактивные запросы пароля. При недоступной аутентификации верни причину и используй одобренный доступ среды. Для Windows выбери включённый транспорт и оболочку по [руководству Windows Server](windows-server.md).

При удалённом запуске локальный массив аргументов защищает границу локального процесса, но удалённая оболочка получает строку команды. Используй заранее определённую команду или проверяемый скрипт с передачей структурированных входов отдельно. Ключи, пароли и приватные материалы держи в штатном credential store или SSH agent. Проверяй диагностические данные до вывода в отчёт.

Сверь идентичность хоста и фактическую учётную запись по результату до выполнения задачи. Для изменения записывай начальное состояние, применяй только запрошенное действие, перечитывай состояние и выполняй пользовательскую проверку. `ssh` возвращает удалённый exit code или 255 при ошибке соединения. При разрыве сессии после записи сначала проверь, завершилось ли удалённое действие, и затем решай вопрос повтора. Для долгой операции зафиксируй ограничение времени и способ проверить её состояние через отдельную сессию. [OpenSSH ssh(1)](https://man.openbsd.org/ssh.1) · [OpenSSH ssh_config(5)](https://man.openbsd.org/ssh_config.5) · [Исходники OpenSSH](https://github.com/openssh/openssh-portable)

Для проверки уже управляемого парка используй существующий inventory и runner. [Ansible](https://github.com/ansible/ansible) подходит для повторяемых изменений, [pytest-testinfra](https://github.com/pytest-dev/pytest-testinfra) для независимых проверок Linux-хоста, а [pyinfra](https://github.com/pyinfra-dev/pyinfra) для репозиториев, где операции по SSH уже описываются на Python. Выбирай инструмент по устройству проекта и целевой проверке.
