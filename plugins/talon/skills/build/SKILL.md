# Talon · Разработка

Доведи идею до первого рабочего пользовательского сценария или дай план, по которому его можно собрать. Для запроса о плане изучи контекст и предложи шаги. Когда пользователь просит реализовать, выполни разрешённый объём по этому плану и проверь результат.

## Выбери объём первой версии

1. Определи пользователя, его задачу и наблюдаемый результат. Для существующего проекта прочитай инструкции, найди нормальную точку входа, похожую реализацию и действующие команды проверки. Для нового проекта опирайся на ограничения пользователя и выбирай обратимые решения.
2. Предложи один первый сквозной сценарий. Он должен давать результат от реального входа до видимого выхода и проверяться на маленьком наборе данных. Вынеси второстепенные сценарии в следующий этап. Если ценность самой идеи сомнительна, предложи самый дешёвый способ проверить её до большой реализации.
3. Найди предпосылку, способную изменить весь план, например доступ к данным, поддерживаемую среду или внешний API. Проверь её раньше зависимой работы. Явно отмечай допущения, которые меняют решение. При развилке с заметными затратами дай одну рекомендацию и объясни, какое ограничение определило выбор.

Для карты незнакомого модуля или оценки влияния изменения на несколько компонентов используй локальный [Graphify](references/graphify.md), если требуется обзор связей. Начинай с конкретного символа или участка проекта.

## Разложи работу на шаги

- Расположи задачи по зависимостям и пользовательской ценности. Для каждого шага укажи действие, затронутый компонент или артефакт и наблюдаемый критерий готовности. Ориентир для плана небольшой задачи — несколько шагов, которые можно проверить по отдельности.
- Сначала проведи узкий рабочий сценарий через существующие границы, затем добавь ошибки, права, переход со старых данных и восстановление там, где это влияет на результат. Если сценарий удаляет или объединяет данные, явно назови правило и способ проверить результат до применения. Для рискованного изменения выдели отдельный эксперимент или пилот с критерием продолжения.
- Для сложного проекта поручай агентам независимые исследования, если это ускорит выбор архитектуры или проверку рисков. Передавай реализацию только с назначенными путями и согласованными контрактами. Объединяй результаты в один порядок действий.
- При реализации сверяй каждый значимый этап с критерием приёмки. Корректируй план по фактическому состоянию проекта. Для проверки исправления или готовности сборки передай версию, сценарии и условия приёмки в `$talon:qa`. Для запуска передай подтверждённые возможности, аудиторию и текущую стадию в `$talon:launch`.

## Что выдать

Дай рекомендуемый первый шаг, затем упорядоченный план с зависимостями и критериями приёмки. Назови риски и решения, которые реально влияют на последовательность. Конкретизируй первый шаг до действия, которое можно начать сейчас. Сроки давай диапазоном с предпосылками, если пользователь их запросил и есть данные для оценки.
