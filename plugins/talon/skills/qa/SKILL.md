# Talon QA

Веди задачу до проверяемого результата. На старте выясни ожидаемое поведение, затронутый сценарий и точную версию или состояние diff. Прочитай инструкции проекта. Ищи QA-плейбук в ссылках из `AGENTS.md`, документации по тестированию или README существующего QA-раннера. Используй существующий runner, сохраняй изменения пользователя и проверяй, что результаты относятся к итоговому коду.

Если риск затрагивает связи между модулями, используй [Graphify](../build/references/graphify.md) для поиска возможных вызывающих путей и выбора регрессий. Явно запрошенный пентест через Strix проводи по [отдельному сценарию](../pentest/SKILL.md).

## Режим работы

- **Аудит** для «проверь», «найди баги», «покажи проблемы». Читай исходники, запускай проверки на изолированных данных, собирай доказательства. Файлы продукта и тестов доступны только для чтения. Побочные эффекты тестов ограничь временными артефактами и согласованным тестовым окружением.
- **Исправление** для «почини», «проверь и исправь». Воспроизведи дефект, внеси минимальную правку и проверь исходный сценарий и соседние варианты. Сохрани регрессию для существенного исправления, если существующие тесты её пропускают и новый тест можно надёжно воспроизвести.
- **Проверка релиза** для «можно выкатывать?», «проверь релиз». Проверь конкретный diff или сборку и назови обязательные проверки по рискам. Действия по публикации, деплою, изменениям production и внешним сообщениям определяются отдельным запросом и доступами.

## Команда

Текущий агент ведёт задачу, делегирует независимые части и сверяет доказательства. Для небольшой локальной правки выполни достаточную проверку без обязательной команды. Для широкого аудита, релиза или существенного изменения запусти отдельного специалиста по затронутой границе и назначь независимого ревьюера на итоговое состояние.

| Роль | Задача |
| --- | --- |
| `talon-investigator` | Минимальное воспроизведение и проверка причины. |
| `talon-browser` | Пользовательские сценарии, роли, UI, сеть, Playwright. |
| `talon-api` | HTTP-контракт, данные, повторы, гонки и частичный отказ. |
| `talon-windows` | PowerShell, установщик, обновление и нативный Windows. |
| `talon-fixer` | Локальная правка в назначенных файлах и целевая регрессия. |
| `talon-reviewer` | Независимая попытка опровергнуть исправление или готовность релиза. |

Выбирай только нужные роли и запускай независимые проверки параллельно в пределах доступных слотов. Ожидай результат только по идентификатору успешно запущенного подагента. Если именованный профиль недоступен, передай ту же задачу доступному подагенту с чёткой ролью и ограничениями. Если делегирование недоступно, выполни доступные проверки сам и зафиксируй, что независимая проверка отсутствует. Для командной работы и проверки релиза прочитай [регламент](references/team-workflow.md). Для конкретного риска прочитай подходящий раздел [сценариев отказа](references/failure-testing.md). Для выбора инструмента открой [справочник](references/toolbox.md).

## Что считать проверкой

1. Установи контракт и получи воспроизводимое отклонение. Для существенного исправления покажи, что один и тот же сценарий обнаруживает ошибку на исходном коде и проходит после правки. Если исходный прогон невозможен, укажи причину и уровень полученного доказательства.
2. Повтори сценарий на финальном состоянии и проверь подходящую негативную ветку. Добавь обязательные команды проекта по затронутой области. Не ослабляй ожидания теста и не объявляй повторный удачный прогон исправлением flaky-теста.
3. Проверяй на требуемой границе. Локальный HTML и mock дают частичное покрытие. Транзакцию, браузерный E2E, права службы и установщик подтверждай на подходящем стенде, сборке и ОС. В протоколе укажи среду, команду, результат и артефакт или причину пропуска.
4. Сверь итоговый diff и отчитайся о подтверждённых дефектах, исправлениях, доказательствах и пробелах. Для проверки релиза выдай один статус из регламента и перечисли условия, которые реально повлияли на решение. Если остались блокеры, укажи, какой снять первым и каким прогоном подтвердить результат. Храни сырой вывод приватно и удаляй из сводки секреты и персональные данные.
