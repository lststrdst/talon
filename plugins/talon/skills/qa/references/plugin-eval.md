# Оценка навыков и плагинов Codex

Выбери фактическую цель. Для навыка это папка с `SKILL.md`, для плагина это папка с `.codex-plugin/plugin.json`. В репозитории Talon укажи `plugins/talon`. Если пользователь явно просит оценить установленный Talon, возьми папку пакета, найденную по пути загруженного навыка.

Начни со статического анализа. Ищи проверенный `plugin-eval` по пути Talon или в `PATH`. При наличии исходников [OpenAI Plugin Eval](https://github.com/openai/plugins/blob/main/plugins/plugin-eval/README.md) можно вызвать `node plugins/plugin-eval/scripts/plugin-eval.js` из репозитория OpenAI Plugins. CLI требует Node.js 20 или новее.

```sh
talon_eval="$HOME/.local/share/talon/bin/plugin-eval"
if [ ! -x "$talon_eval" ]; then
  talon_eval="$(command -v plugin-eval)" || exit 1
fi
"$talon_eval" analyze ./plugins/talon --format json
```

При недоступности CLI проверь манифест, относительные ссылки и YAML навыков вручную и сообщи, какой проверкой располагаешь. В отчёте Eval сверь причины предупреждений с исходниками и требованиями целевой установки. Например, отсутствие полей для витрины может снизить оценку у работающего пакета, установленного из GitHub. Для сравнения версий передай два сохранённых JSON-отчёта команде `compare`.

Статический отчёт показывает структуру и оценку объёма инструкций. По запросу на проверку поведения задай критерии и сверь с ними фактические действия модели. Например, запрос только на аудит должен сохранить файлы, а запрос на новую функцию должен загрузить Build.

Перед `benchmark` проверь конфигурацию и доступность навыка внутри тестового сеанса. Используй синтетическую фикстуру и отдельный тестовый профиль. Раннер может копировать настройки и авторизацию Codex и наследовать переменные среды. Для проверочных команд учитывай их права отдельно. `benchmark` записывает прогоны и расход токенов, а критерии из списка в конфиге проверяет человек или отдельный скрипт.
