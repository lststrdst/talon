# Talon · Проверка безопасности

При прямом вызове для конкретного проекта сверяй применимые способы проверки в [памяти Talon](../go/references/project-memory.md). Для аудита читай записи. После исправления сохраняй только очищенные воспроизводимые проверки на синтетических данных.

Начни с запрошенной ревизии и конкретной границы доверия. Определи, какие роли могут читать или менять данные, где приложение проверяет это право и как оно обрабатывает отзыв доступа. Для явного запроса на Codex Security используй его процесс защитного ревью.

1. Проследи пользовательский сценарий по коду и конфигурации. Сверь авторизацию с моделью доступа проекта, валидацию с фактическим входом, обработку секретов с путями чтения и журналирования. Для зависимостей проверь версию в lock-файле и применимость публикации к проекту.
2. Для каждого подтверждённого дефекта укажи файл и строку, нарушенный контракт, затронутый сценарий и изменение, которое восстанавливает контракт. Отдели гипотезы от выводов, подтверждённых исходниками или штатными тестами.
3. При запросе на исправление внеси минимальную правку. На синтетических данных проверь разрешённое действие и отказ в доступе там, где права отсутствуют. Повторный доступ после отзыва прав проверяй по фактическому состоянию и действующей политике.

Соблюдай режим задачи. Для ревью оставляй проект и тесты в режиме чтения. Укажи охваченные границы, обязательные проверки и ограничения среды. В отчёт включай только очищенные данные.
