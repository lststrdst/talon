# Talon · Автоматизация процессов

Начни с результата, триггера и получателя. Найди существующий workflow, экспорт, тестовые данные и версию раннера в репозитории нужного компонента. Используй [память Talon](../go/references/project-memory.md) и уже доступный движок. При задаче по n8n проверь доступные коннекторы и команды проекта. Если нужной инструкции не хватает, используй [Autoskills](../autoskills/SKILL.md) по конкретному узлу или этапу. Сверь выбранный навык с [официальными навыками n8n](https://github.com/n8n-io/skills) и версией инстанса.

Если n8n уже подключён по MCP, укажи точный проект и workflow. Для чтения используй доступные `search_workflows` и `get_workflow_details`. Для SDK-описания примени `validate_workflow`, если инстанс предоставляет этот инструмент. После разрешённого изменения прочитай сохранённые соединения. Доступность MCP и набор инструментов зависят от версии, конфигурации и прав. [Подключение n8n MCP](https://docs.n8n.io/build/ways-of-building-workflows/connect-to-n8n-mcp-server/), [жизненный цикл workflow](https://github.com/n8n-io/skills/tree/main/skills/n8n-workflow-lifecycle-official).

## Спроектируй и собери

1. Зафиксируй вход, схему данных, результат, внешние записи и условие успешного выполнения. Для расписания проверь часовой пояс. Для webhook проверь метод, проверку источника и ожидаемый HTTP-ответ.
2. Возьми существующий экспорт или подготовь небольшую JSON-фикстуру в формате целевой версии. Серверный CLI выгружает один workflow командой `n8n export:workflow --id=<ID> --output=workflow.json`. Оставь ссылки на тестовые credentials и синтетические значения. В экспорт могут попасть имена и идентификаторы credentials, заголовки HTTP, данные из `pinData` и реальные адреса. Проверь их перед передачей файла и открытием его во внешнем сервисе. [Импорт и экспорт n8n](https://docs.n8n.io/workflows/export-import/).
3. Для операций записи определи стабильный ключ события. Используй ключ идемпотентности у получателя или атомарную дедупликацию. Если запись могла пройти до сбоя, сверь её состояние перед повтором. Ограничь повторы временных сбоев и соблюдай `Retry-After`, когда его возвращает сервис. Сохрани причину постоянного отказа и данные, достаточные для безопасного повтора. [Обработка ошибок n8n](https://docs.n8n.io/flow-logic/error-handling/).

## Проверь локально

Подготовь синтетический вход. Подмени узлы, которые пишут данные, отправляют сообщения или обращаются к рабочим системам, на локальные заглушки либо тестовые операции. Проверь также Code, вызовы подчинённых workflow и доступы тестовых credentials. Ручной запуск и MCP `test_workflow` могут реально выполнять часть узлов. [Тестирование через MCP](https://github.com/n8n-io/skills/blob/main/skills/n8n-workflow-lifecycle-official/references/TESTING.md).

Если проект уже использует локальный n8n, импортируй проверенную копию в изолированный инстанс. Серверный CLI `n8n import:workflow --input=workflow.test.json` может перезаписать workflow с тем же ID, поэтому используй отдельную базу. Для ручного триггера запусти `n8n execute --id <ID>` или выполни workflow в редакторе. Это команды выполнения. Для webhook выбери **Listen for test event** и отправь запрос на показанный **Test URL**. Подставь локальный порт и путь тестового узла.

```sh
curl -sS -i --max-time 5 -X POST \
  -H 'Content-Type: application/json' \
  --data '{"eventId":"test-001","kind":"sample"}' \
  'http://127.0.0.1:5678/webhook-test/example'
```

Проверь успешный вход, ошибку валидации и повтор с тем же `eventId`. Если нужен устойчивый повтор, смоделируй временный отказ заглушки и проверь число попыток и конечный результат. Зафиксируй версию, команду или ID выполнения, фактический ответ и число записей в тестовом получателе. При отсутствии раннера проверь структуру и выражения доступными средствами проекта и укажи, что требуется для прогона в движке. Публикацию, активацию расписаний и вызовы внешних сервисов выполняй в рамках явно запрошенного этапа. [Команды n8n](https://github.com/n8n-io/n8n-docs/blob/main/docs/deploy/host-n8n/configure-n8n/use-the-command-line.md), [тестовый webhook](https://github.com/n8n-io/n8n-docs/blob/main/docs/integrations/builtin/core-nodes/n8n-nodes-base.webhook/workflow-development.md).
