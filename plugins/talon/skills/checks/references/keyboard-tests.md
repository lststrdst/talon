# Клавиатурные проверки в браузере

Открой этот сценарий, когда пользовательский путь зависит от клавиатуры, например при открытии модального диалога, переходе фокуса и закрытии. Проверь путь в штатном браузерном проекте Playwright на предсказуемой тестовой странице. Для меню, вкладок и комбобоксов сверяй клавиши и ожидаемые переходы с шаблоном соответствующего виджета. [WAI-ARIA APG](https://www.w3.org/WAI/ARIA/apg/patterns/)

## Адаптируй сценарий

1. Скопируй [шаблон модального диалога](../assets/keyboard/modal-dialog.spec.cjs) в тестовый каталог проекта. Используй его `baseURL`, браузерный проект и тестовую фикстуру пользователя. Пример открывает и закрывает форму тестового профиля на `/settings`. Шаблон использует `locator.and()`, доступный с Playwright 1.34. [Locator.and](https://playwright.dev/docs/api/class-locator#locator-and)
2. Подставь роли и ожидаемые доступные имена элементов из интерфейса и выбранной локали. Обнови `settingsPath`, число переходов `tabPressesToOpener`, порядок элементов в обеих последовательностях и сообщения проверок. Для контейнера диалога подставь его устойчивый `dialogTestId` или замени `getByTestId()` локатором по существующему DOM-идентификатору. Если перед кнопкой важны промежуточные элементы, проверь их фокус после каждого `Tab`. [Локатор по роли](https://playwright.dev/docs/locators#locate-by-role) · [Локатор по test ID](https://playwright.dev/docs/locators#locate-by-test-id)
3. Укажи предусмотренный продуктом начальный фокус и место возврата. В примере начальный фокус совпадает с первым элементом в порядке `Tab`, а после закрытия возвращается на кнопку открытия. Если начальный фокус должен идти на заголовок или на другой элемент внутри диалога, проверь его отдельно и дойди клавишами до границ последовательности перед проверкой циклического перехода. После закрытия исходная кнопка иногда исчезает. Тогда укажи следующий логический элемент рабочего сценария. В проверке возврата используй подтверждённый фокус внутри диалога как исходное состояние. [Модальный диалог WAI-ARIA APG](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/#keyboard_interaction)
4. Посылай `Tab`, `Shift+Tab`, `Enter` и `Escape` через `page.keyboard.press()`. Проверяй фактический фокус ожидаемого элемента через `toBeFocused()`, а открытие и исчезновение диалога через проверки видимости. При открытии проверь роль и доступное имя контейнера. При закрытии проверь видимость того же контейнера по устойчивому идентификатору, даже если роль или имя успели измениться. `locator.press()` сначала фокусирует свой элемент. Поэтому для переходов используй клавиатуру страницы и сохраняй фокус, полученный предыдущим действием. [Клавиатура Playwright](https://playwright.dev/docs/api/class-keyboard#keyboard-press) · [Проверка фокуса](https://playwright.dev/docs/api/class-locatorassertions#locator-assertions-to-be-focused) · [Locator.press](https://playwright.dev/docs/api/class-locator#locator-press)

## Запусти и разбери результат

Из корня проекта запусти тест штатной командой. Например, для установленного Playwright Test и проекта `chromium`:

```sh
npx --no-install playwright test tests/modal-dialog.spec.cjs --project=chromium
```

Для регрессии прогони те же ожидания на версии с дефектом и после исправления. Зафиксируй браузер, исходное состояние, действие, ожидаемый и фактический фокус либо состояние диалога. Для проверяемого прогона сохрани JUnit с количеством выполненных, упавших и пропущенных тестов и trace упавшего сценария. [Браузерные проверки](browser.md#отчёт-и-trace)
