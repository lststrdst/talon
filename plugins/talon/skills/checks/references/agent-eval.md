# Проверка результата работы агента

Используй [agent_eval.py](../scripts/agent_eval.py), чтобы проверить результат на двух одноразовых задачах. Скрипт работает с Python 3.9 и новее, а для задачи Git нужен установленный `git`. Оценщик работает локально и не обращается к модели или внешнему сервису.

| Задача | Проверяемый результат |
| --- | --- |
| `git-selective-commit` | На `main` появился один коммит с ожидаемой правкой README и указанным синтетическим авторством. Индекс и рабочий файл черновика сохранили свои разные версии. Временная заметка осталась без изменений вне индекса. С `--push` оценивается совпадение хешей `main` в рабочей копии и соседнем локальном `origin.git`. |
| `sqlite-retry-regression` | Исходный сервис сохранился побайтно. Один и тот же тест обнаруживает дубль на исходном сервисе и проходит на исправленном, а отдельный тест подтверждает две записи для разных ключей. Оценщик независимо перечитывает SQLite до повтора, в точке потери подтверждения и после повтора. Два дополнительных прогона проверяют, что тот же тест обнаруживает ошибку отдельно в идентификаторе ответа и идентификаторе сохранённой строки. |

## Как повторить

Из корня исходников Talon выполни команды ниже. В установленном пакете используй путь к `skills/checks/scripts/agent_eval.py`.

```sh
talon_judge="$PWD/plugins/talon/skills/checks/scripts/agent_eval.py"
talon_eval_run=$(mktemp -d)
python3 "$talon_judge" prepare git-selective-commit "$talon_eval_run/git" --push
python3 "$talon_judge" prepare sqlite-retry-regression "$talon_eval_run/retry"
```

Открой новый сеанс агента в каталоге `workspace/` каждого сценария и передай содержимое соответствующего `PROMPT.md`. Для сравнения подготовь новые каталоги для каждого агента. Используй один текст задания, одинаковые доступы, ограничения и версию оценки. Это подходит для Codex и локальной модели через рантайм, который умеет читать и менять файлы, запускать команды и сохранять результат. Дай агенту доступ к подготовленной рабочей папке и, если выбран `--push`, к соседнему `origin.git`. Храни исходники и отчёт оценки вне доступной кандидатам рабочей папки. Используй подготовленные синтетические данные и отдельный сеанс рантайма.

После работы агента запусти независимую оценку.

```sh
python3 "$talon_judge" grade git-selective-commit "$talon_eval_run/git"
python3 "$talon_judge" grade sqlite-retry-regression "$talon_eval_run/retry" --run-candidate-tests
```

`pass` даёт код 0, `fail` даёт 1, `error` даёт 2. `checks` показывает отдельные критерии. В `evidence` Git показывает хеши, а SQLite — число выполненных, упавших и пропущенных тестов по версиям сервиса. Пустой набор, пропуски, ошибки загрузки и падение вне наблюдаемого сценария не подтверждают регрессию.

## Повтор теста SQLite

Оценивай только созданную командой `prepare` фикстуру и передавай `--run-candidate-tests` после проверки источника `test_retry.py`. Для каждого контрольного прогона оценщик переносит этот файл и свою версию сервиса в новый временный каталог. На macOS нужен `sandbox-exec`, на Linux — `bwrap` с доступной изоляцией через пространства имён. Среда не получает настройки и переменные авторизации рантайма, а песочница ограничивает сеть и запись. На Ubuntu 24.04 AppArmor может запретить создание изолированной сети даже при установленном bubblewrap. Оценщик проверяет запуск изоляции перед тестами и возвращает `retry_sandbox_unavailable`, когда текущий пользователь не может её запустить. Для такой машины укажи SQLite как непроверенный или используй подготовленный тестовый раннер. Для кода из незнакомого источника используй отдельную одноразовую виртуальную машину.

Оценивай выбор маршрута по журналу действий отдельно от JSON результата. Для маршрута нужны события загрузки навыка или вызова команды. Сохраняй вместе версию Talon, модель, рантайм, JSON оценки и, если есть, очищенный журнал. После изменения оценщика повтори положительные и отрицательные контроли из `tests/test_agent_eval.py` в исходниках.
