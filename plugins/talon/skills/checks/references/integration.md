# Интеграционные проверки и инфраструктура

Начни с теста проекта и его фикстуры. Если профиль Compose в CI уже поднимает нужные зависимости и позволяет воспроизвести сбой, запусти целевой тест через него. Testcontainers подходит, когда тесту нужен отдельный экземпляр зависимости с временем жизни, привязанным к тесту или набору тестов. Для проверки применения роли Ansible используй сценарий Molecule. Для проверки состояния уже подготовленного Linux-хоста подходит Testinfra.

## Testcontainers для Node.js и Python

- Сверь версию Node.js или Python с метаданными выбранного пакета и lock-файлом проекта. Проверь из среды тест-раннера доступ к Docker API, наличие образа для архитектуры стенда и подключение к назначенному порту. Для Node.js используй `testcontainers` или специализированный модуль, например `@testcontainers/postgresql`. В Python поддержка PostgreSQL поставляется как `testcontainers[postgres]`. Драйвер БД берётся из зависимостей проекта. [Среды запуска Node.js](https://node.testcontainers.org/supported-container-runtimes/) · [Модуль PostgreSQL для Node.js](https://node.testcontainers.org/modules/postgresql/) · [Testcontainers для Python](https://testcontainers-python.readthedocs.io/en/latest/)
- Используй версию образа и расширения, соответствующие проверяемой среде. Возьми адрес и порт из фикстуры. Дождись готовности по проверке, подходящей для операции, например запросом к БД через драйвер. Примени штатные миграции и прогони сценарий через обычную точку входа приложения. Для миграции с предыдущей версии подготовь поддерживаемую ревизию схемы с синтетическими данными. [Стратегии ожидания в Node.js](https://node.testcontainers.org/features/wait-strategies/)
- Проверь состояние после записи. При риске частичного отказа вызови ожидаемую ошибку внутри операции и сверь состояние данных после отката. Для очереди с повторной доставкой обработай сообщение с тем же ключом и проверь, что итоговый эффект возник один раз. Закрывай клиент и удаляй ресурсы этого прогона при завершении теста, включая сбой. Для Python используй контекстный менеджер или фикстуру с очисткой. [Жизненный цикл контейнера в Node.js](https://node.testcontainers.org/features/containers/#stopping-a-container) · [Пример PostgreSQL в Python](https://testcontainers-python.readthedocs.io/en/latest/#getting-started)

## Molecule для ролей и playbook Ansible

Проверь версию `ansible-core` и зависимости сценария. Например, сценарий, который управляет Podman через Ansible, требует доступ к Podman и коллекцию `containers.podman`. Сверь inventory, `create`, `destroy` и `test_sequence` перед запуском. Для проверки системной перезагрузки или поведения ядра выбери одноразовую ВМ с целевой ОС. Для проверки работы службы под systemd используй стенд, где он запущен как PID 1. [Требования Molecule](https://docs.ansible.com/projects/molecule/installation/#requirements) · [Тестирование роли](https://docs.ansible.com/projects/molecule/getting-started-roles/) · [Контейнер с systemd](https://docs.ansible.com/projects/molecule/guides/systemd-container/)

Запусти `molecule test --scenario-name "$talon_scenario"` для выбранного сценария на одноразовой цели. Проверь успешный `converge` и ожидаемое состояние в `verify.yml`, например права файла и ответ запущенной службы. Для подтверждения идемпотентности прогони `idempotence` и ожидай ноль изменений при повторном применении. После прохождения или сбоя проверь очистку ресурсов сценария. [Действия и последовательности Molecule](https://docs.ansible.com/projects/molecule/workflow/) · [Тестирование playbook](https://docs.ansible.com/projects/molecule/getting-started-playbooks/)

## Testinfra для Linux

Используй установленный в окружении проекта `pytest-testinfra` и подходящий способ подключения. Для SSH сначала сверь алиас, учётную запись, известный ключ хоста и доступ из текущего раннера. Просмотри конфигурацию, тесты и фикстуры, чтобы подтвердить список целей перед запуском. Пример для одного согласованного стенда и существующего набора проверок.

```sh
python -m pytest --hosts="ssh://$talon_test_host" "$talon_infra_tests"
```

Выбери утверждения по контракту, например владельца и режим файла, состояние службы и включение при загрузке. Для инвентаря Ansible явно укажи файл и точную тестовую цель. Подтверди, что pytest собрал нужные тесты и выполнил их на выбранном хосте. [Способы подключения Testinfra](https://testinfra.readthedocs.io/en/latest/backends.html) · [Проверки файлов и служб](https://testinfra.readthedocs.io/en/latest/modules.html)

Отметь запуск и результат проверки готовности зависимости. Результат интеграции привяжи к выполненным утверждениям о приложении, данных или хосте. В отчёте укажи команду, код завершения, версию образа или ОС и результат очистки, если стенд создавался прогоном. При недоступной среде перечисли выполненные проверки и укажи, какой прогон требует этой среды.
