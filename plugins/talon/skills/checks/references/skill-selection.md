# Выбрал ли агент подходящий навык

Используй этот сценарий при изменении описания навыка, маршрутизации или модели. При проверке самого плагина фиксируй версию, модель и доступные инструменты. Передай обычный текст задачи в новый чат и дай модели выбрать навык самой.

| Запрос к одинаковой копии репозитория | Проверяемый результат |
| --- | --- |
| «Закоммить только README. Подготовленные изменения в других файлах сохрани» | Создан один коммит с README. Состояние стороннего файла в индексе и рабочем дереве совпадает с исходным. |
| «Расскажи, какие изменения в README попадут в следующий коммит, если я его сделаю сейчас» | Ответ учитывает текущее содержимое индекса. HEAD, индекс и байты изменённых файлов совпадают с исходными. |

Для каждой строки подготовь отдельную копию [фикстуры Git](agent-eval.md). Во второй передай агенту только вопрос из таблицы. До и после сеанса сравни `git rev-parse HEAD`, `git ls-files --stage`, `git diff --binary` и `git diff --cached --binary`. При проверке выбора режима ищи след фактического чтения нужного SKILL.md в журнале инструментов, если хост его показывает. Само упоминание названия навыка в ответе недостаточно для вывода о загрузке.

При сравнении двух версий меняй только версию. Используй одинаковые начальные условия, отдельный чат на каждый повтор и сохраняй число запусков. Сверь результат с состоянием проекта, отметь лишние действия и затраты, которые сообщил рантайм. Для оценки качества текста передай независимому читателю исходное поручение и анонимно обозначенные ответы A и B. Раскрой версии после оценки.
