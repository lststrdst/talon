# Сверка интерфейса с макетом Figma

Открой сценарий, когда есть конкретный кадр Figma или его экспорт и нужно проверить реализацию в браузере. Зафиксируй ссылку на кадр, версию макета, URL и ревизию реализации. Выбери одинаковые ширину экрана, данные, состояние интерфейса, тему и локаль. Для нескольких брейкпоинтов бери отдельный кадр на каждую ширину.

1. Получи скриншот кадра через `get_screenshot` в Figma MCP или попроси экспорт кадра при доступе через инспектор Figma. Сверь размеры результата с размерами кадра, поскольку MCP может уменьшить изображение. При использовании REST API выбери `GET /v1/images/:key` с `format=png` и `scale=1`, а для размеров кадра и слоёв используй `GET /v1/files/:key/nodes`. [Figma MCP](https://developers.figma.com/docs/figma-mcp-server/tools-and-prompts/), [Figma REST API](https://developers.figma.com/docs/rest-api/file-endpoints/).
2. Сохрани скриншот реального браузера при заданных viewport и масштабе. Дождись нужных данных и шрифтов. Для интерактивного состояния используй подготовку страницы штатного теста проекта, затем снимай тот же экран. Приведи скриншоты к одинаковому обрезу и сравни их рядом. [Playwright Screenshots](https://playwright.dev/docs/screenshots).
3. Сопоставь элементы с однозначными селекторами. Измерь нужные размеры и координаты в инспекторе Figma и браузере. Для геометрии `absoluteBoundingBox` вычти координаты кадра из координат дочернего слоя. Выбери допуск до сравнения, учитывая дробные пиксели. Отдельно проверь шрифты, цвета и иконки по паре изображений и стилям. [Типы узлов Figma](https://developers.figma.com/docs/rest-api/file-node-types/).
4. Для дефекта укажи элемент, состояние, ширину, ожидаемое значение, фактическое значение, разницу и оба скриншота. При исправлении повтори ту же проверку и сохрани снимок новой версии.

## Проверка геометрии в Playwright

[compare-layout.cjs](../assets/design-qa/compare-layout.cjs) принимает URL, JSON с эталонной геометрией и путь к новому PNG. В JSON задай `viewport`, селектор контейнера `frame`, допустимое отклонение `tolerance` в CSS-пикселях и массив `targets`. Для каждого `selector` перечисли нужные `x`, `y`, `width` или `height` в `bounds`. Координаты отсчитываются от левого верхнего угла `frame`. Скрипт создаёт чистую страницу, ждёт загрузки и шрифтов, снимает контейнер и выводит JSON с измерениями. Код `0` означает попадание в допуск, `1` означает расхождение, `2` означает сбой сбора. Для авторизации и динамических состояний перенеси измерение в штатный Playwright-тест с подготовкой состояния.

Для локальной проверки используй рабочий `playwright` проекта с установленным Chromium. Если раннер запускается из каталога навыка, укажи путь к установленному Playwright через `NODE_PATH`. Для установленного Chrome задай абсолютный путь к браузеру в `TALON_CHROMIUM_EXECUTABLE`. Выполни команды из каталога с [fixture.html](../assets/design-qa/fixture.html) и [fixture-spec.json](../assets/design-qa/fixture-spec.json).

```sh
talon_layout=$(mktemp -d)
node compare-layout.cjs "file://$PWD/fixture.html" fixture-spec.json "$talon_layout/actual.png"
node compare-layout.cjs "file://$PWD/fixture.html?aligned" fixture-spec.json "$talon_layout/control.png"
```

Синтетический эталон задаёт `x=24`. В Chrome 157 и Playwright 1.62.1 дефект дал `x=40`, разницу `+16` CSS-пикселей и код `1`. Контрольный вариант дал `x=24` и код `0`. Оба файла были PNG размером 360×240. Для проверки самого макета используй доступный кадр Figma и снимок реализации.
