# Проверки свойств данных

Применяй, когда нужно проверить функциональный контракт на множестве обычных входов. Например, экспорт с последующим импортом сохраняет содержимое и порядок строк, повторная нормализация даёт тот же результат, а число элементов при разбиении и сборке сохраняется. Начни со штатного раннера и средств генерации проекта.

1. Определи точку входа, допустимые данные и проверяемое свойство по контракту. Для импорта и экспорта проверь обратный проход и обмен данными с независимой реализацией в обе стороны. Один обратный проход может скрыть взаимно компенсирующие ошибки.
2. Задай ограниченный генератор с нужными граничными значениями. Проверь пустые данные, одну запись, предельные допустимые размеры и значимые комбинации. Используй синтетический ввод и одноразовые артефакты, если проверка пишет файлы. [Стратегии Hypothesis](https://hypothesis.readthedocs.io/en/latest/reference/strategies.html)
3. Запусти целевой тест. Запиши ревизию, команду, версии Python и раннера, код выхода, число тестов и статистику генерации. При падении сохрани минимизированный пример и ожидаемый и фактический результаты. Повтори пример на той же версии, например через `@example`, и проверь то же утверждение после исправления. [Повтор падений в Hypothesis](https://hypothesis.readthedocs.io/en/latest/tutorial/replaying-failures.html)

## Локальный пример с pytest и Hypothesis

В CSV с разделителем `,` и кавычками `"` сохраняются порядок строк, пустые ячейки, пробелы, переносы внутри полей и состав символов Unicode. Допустима пустая таблица, каждая строка содержит хотя бы одно поле. Генератор ограничен пятью строками, пятью полями в строке и 16 символами в поле. Для каждого набора строк проверяются обратный проход в проекте, чтение экспорта стандартным парсером и чтение стандартного CSV проектом. Стандартный читатель и писатель Python используют один диалект `excel`. Два фиксированных теста сохраняют пример с кавычками, переносом строки, Unicode и пустым полем. [Шаблон тестов](../assets/property/csv_properties.py) · [Модуль `csv` в Python](https://docs.python.org/3/library/csv.html)

Для демонстрации скопируй оба файла из каталога навыка `checks` во временную папку. Команда создаёт окружение Python 3.9 или новее, устанавливает тестовые зависимости и сохраняет свежий отчёт JUnit.

```sh
talon_checks='/абсолютный/путь/к/checks'
talon_property_dir=$(mktemp -d)
cp "$talon_checks/assets/property/csv_properties.py" \
  "$talon_checks/assets/property/csv_example.py" "$talon_property_dir/"
python3 -m venv "$talon_property_dir/.venv"
"$talon_property_dir/.venv/bin/python" -m pip install pytest hypothesis
(
  cd "$talon_property_dir" && .venv/bin/python -m pytest -q \
    --hypothesis-show-statistics --junitxml=report.xml csv_properties.py
)
```

Для проекта с этим контрактом подставь штатные чтение и запись в адаптере, сохранив интерфейсы `write_rows(rows) -> str` и `read_rows(text) -> list[list[str]]`. Прогони те же утверждения в среде проекта с его версиями зависимостей. `derandomize=True` делает быстрый прогон повторяемым при тех же версиях Python и Hypothesis и том же тесте. В отчёте различай три теста pytest и число сгенерированных примеров для свойства. [Адаптер CSV](../assets/property/csv_example.py) · [Настройки Hypothesis](https://hypothesis.readthedocs.io/en/latest/reference/api.html#hypothesis.settings)

В существующем проекте сохрани адаптированную регрессию под именем, которое обнаружит его тестовый набор, например `test_csv_properties.py` для pytest. Для JS/TS с установленным fast-check передай генераторы в `fc.property` и проверяй то же свойство через `fc.assert` внутри штатного теста. [Пример fast-check](https://fast-check.dev/docs/introduction/getting-started/)
