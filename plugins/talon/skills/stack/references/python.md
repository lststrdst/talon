# Python, FastAPI и утилиты

## Среда и команда

- Сверь `requires-python`, lock или requirements, образ Docker и версию Python в CI. В репозитории с API, CLI и отдельными расширениями проверь, из какой папки запускается каждый runner. Если используется окружение проекта, выполняй `python -m` тем же интерпретатором для импорта и тестов.
- Найди конфигурацию pytest, unittest, Ruff или другого инструмента в дереве и CI. Для pytest используй `python -m pytest` с нужной тестовой целью. Для unittest используй обнаружение и шаблон файлов, принятые в CI. Проверь, сколько тестов реально собрано и выполнено. `compileall` даёт отдельную проверку синтаксиса. Импорт приложения и работу зависимостей проверяй штатным тестом.
- Для CLI проверь вызов так, как его запускает пользователь: `python script.py`, модуль или console script из `[project.scripts]`. Проверь код выхода, stdout/stderr, Unicode, изменение файлов, повтор и отказ из-за некорректного ввода. Для обработки файлов и изображений используй временный каталог и небольшую синтетическую разметку.

## API и фоновые зависимости

- Для FastAPI найди фабрику приложения, схему Pydantic и роутер. Сверь вход, JSON-ответ и ошибки через реальный HTTP-контракт теста. Используй fixture проекта и `TestClient` или асинхронный клиент в зависимости от контекста. Если поведение зависит от lifespan, проверь, что тест его запускает. После подмены зависимостей очисти overrides через fixture проекта.
- Для SQLAlchemy и SQLite используй существующую тестовую сессию или временную файловую БД. При `:memory:` проверь, что все нужные соединения действительно видят одну БД. Для PostgreSQL, миграций и очередей открой [проверку данных](data.md).
- Для векторного поиска, локальной модели и интеграций сначала проверь контракт на подменах и небольшом наборе данных. Для изменения модели, индекса или ускорителя добавь прогон в соответствующей среде с наблюдаемым результатом. Для внешних сообщений и webhook используй тестовый обработчик или стаб.
