# Talon · Стек проекта

Определи, какой компонент меняется, его рабочий каталог и целевую платформу. Сначала найди манифест, lock-файл и профиль CI именно этого компонента. Если стек и команда проверки уже подтверждены, используй их сразу.

При необходимости запусти [detect.py](scripts/detect.py) на Python 3.9+ из каталога этого навыка. В `talon_project` укажи корень нужного проекта. В смешанной папке сузь анализ через `--target` до файла или подпроекта. Допускается убрать `--target`, когда весь выбранный корень относится к задаче.

```sh
python3 "$talon_stack_dir/scripts/detect.py" --project "$talon_project" --target "$talon_component"
```

Скрипт читает ограниченный набор файлов и выдаёт JSON с путями у `signals`, `runners` и ключами объявленных `scripts`. Он не запускает проект. Смотри ближайшие манифесты и признаки, относящиеся к задаче. Родительский манифест может задавать инструмент сборки для всего workspace. Если Python недоступен или результат усечён, найди нужные файлы проекта обычным поиском.

| Признаки | Какое руководство открыть |
| --- | --- |
| Node, JavaScript, TypeScript, React, Next, Vite, Express, NestJS, VS Code или web-манифест | [Web и Node.js](references/web.md) |
| Python, FastAPI, pytest, unittest или Python CLI | [Python и API](references/python.md) |
| PowerShell, C#-лаунчер, WinForms, Windows-скрипты или проект .NET | [Windows-приложения и пакеты](references/windows.md) |
| SQL, PostgreSQL, SQLite, Redis или миграции | [Данные и очереди](references/data.md) |
| Shell, systemd, Docker, Go, Lua, Makefile или OpenWrt | [Системные компоненты](references/systems.md) |

Открой материалы по тем частям, которые реально затронуты. Если для другого стека уже доступен профильный навык, используй его. Учитывай вес доказательств: расширение файла даёт язык, зависимость или конфигурация подтверждает выбранный инструмент, CI уточняет версии и последовательность команд. Метаданные пакета или лаунчера сами по себе не показывают, что исходники для его сборки доступны.

Проверь, что целевые файлы, рабочий каталог, ОС и зависимости для выбранной команды доступны. Различай объявленную команду, её фактический запуск и наблюдаемый результат. Для проверки или реализации выполни относящиеся к задаче команды после сверки их действия. Если результат зависит от отсутствующего файла, среды или разрешённого стенда, назови границу и выполни доступную часть. Для отчёта используй версию инструмента, команду, код завершения и результат тестов.
