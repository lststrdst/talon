# Talon · Сквозные тесты

Выбери путь пользователя из задачи, требований или изменённого кода. Запиши стартовое состояние, действие и видимый результат, по которому тест отличит рабочий сценарий от дефекта. Для поиска багов начни с основного пути, затем проверь один риск по ситуации — возврат назад, повтор отправки, восстановление после перезапуска или изменение размера экрана.

1. **Выбери раннер.** Проверь конфиг, зависимости, существующие тесты и команду CI в целевом компоненте. При неясном стеке используй [детектор проекта](../stack/SKILL.md). Если в проекте есть Maestro Flow, пользователь просит Maestro или для нового мобильного набора ещё нужен раннер, открой [руководство Maestro](references/maestro.md). Для веба, Appium, Detox или штатного тестового фреймворка платформы открой [выбор раннера](references/runner-selection.md).
2. **Подготовь сценарий.** Возьми тестовую сборку и контролируемые данные. Для регрессии добавь тест рядом со штатным набором по правилам проекта. При аудите используй временную копию или файл во временной папке. Предпочитай наблюдаемые состояния, доступные имена или стабильные идентификаторы. Используй ожидания раннера вместо фиксированных пауз.
3. **Запусти тест.** Сверь устройство или браузер, версию сборки, команду и код выхода. Уточни по отчёту раннера, что нужный тест действительно выполнился. После действия проверь конечный эффект. Для сохранения данных закрой и снова открой экран или перечитай состояние через интерфейс. Для повторных прогонов используй описанное начальное состояние.
4. **Разбери падение.** Найди первый шаг, где поведение разошлось с ожиданием. Проверь состояние приложения и пригодность локатора, посмотри скриншот или trace за этот момент и воспроизведи из чистого состояния. Различай дефект продукта, ошибку теста, нестабильный результат и недоступность стенда. Если поручено исправление, повтори тот же тест после правки с исходным ожиданием.

В отчёте укажи сборку, среду, команду, результаты первого и повторного прогонов, ожидаемое и фактическое поведение и ссылку на один артефакт. Отметь заменённые зависимости. Если устройства или сборки нет, можно подготовить тест и точно назвать оставшуюся проверку. В Codex для отдельного поручения по созданию тестов есть профиль `talon-e2e`. Основной агент может выполнить тот же сценарий самостоятельно.
