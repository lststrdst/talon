# Talon

Выбери режим по результату, который нужен пользователю, и прочитай инструкцию перед работой.

- [Разработка](../build/SKILL.md) — разобраться в коде, спланировать или реализовать функцию, написать скрипт Python или PowerShell, выполнить административную задачу на Windows Server или Linux.
- [Дизайн](../design/SKILL.md) — продумать экраны, компоненты, палитру, типографику, адаптивность и доступность с UI/UX Pro Max.
- [Изображения](../visuals/SKILL.md) — сгенерировать фото или иллюстрацию, отредактировать исходник, экспортировать и проверить изображения в продукте.
- [Тестирование](../qa/SKILL.md) — проверить существующее поведение, расследовать или исправить баг, оценить готовность к выпуску. Для нативного интерфейса есть сценарий Agent Desktop.
- [Запуск](../launch/SKILL.md) — подготовить продвижение, анонс, пилот или исследовать обсуждения аудитории через Agent Reach.
- [Автоматизация](../workflows/SKILL.md) — собрать или проверить workflow n8n, webhook, расписание или интеграцию между сервисами.
- [Проверка безопасности](../security/SKILL.md) — провести защитное ревью кода и конфигурации. Явный запрос Codex Security направляй в его собственный процесс.
- [Подбор навыков](../autoskills/SKILL.md) — определить стек проекта и подобрать дополнительные навыки через Autoskills. Для установки используй отдельный этап этого сценария.

Для нового, смешанного или неполного проекта сначала используй [Стек проекта](../stack/SKILL.md), если ещё нужно определить язык, инструменты сборки или проверки по файлам конкретного компонента. Затем продолжи выбранный режим.

Для фичи на нескольких компонентах, продолжения чужой реализации, ревью ветки или контроля совместимости используй [Сквозную разработку](../delivery/SKILL.md) только для нужных этапов.

Для задачи по среде CI, тестовым сервисам, браузерным отчётам или проверяемому прогону открывай [Воспроизводимые проверки](../checks/SKILL.md) на соответствующем этапе.

Для истории Git, GitHub, Reddit или поиска решения в интернете открой [Поиск решений](../research/SKILL.md). В Build и QA подключай его, когда локальная проверка выявила симптом и следующий шаг зависит от upstream или версии.

Для AD DS, LDAP, GPO, DNS, SCIM, YandexADSCIM или администрирования сервисов Яндекса открой [Каталоги, политики и Яндекс](../directory/SKILL.md). Выбери подходящий раздел по сервису и версии.

Если запрос включает несколько этапов, применяй навыки в порядке зависимостей. «Сделай функцию и проверь регрессии» ведёт в Build, затем в QA. «Придумай интерфейс и реализуй» ведёт в Design, затем в Build и QA. «Проверь готовность и подготовь анонс» ведёт в QA, затем в Launch с учётом результата проверки. Сохраняй явные указания пользователя об объёме работы, режиме аудита и специализированных навыках.

Для запроса по уже работающему серверу выбери Build, чтобы подключить руководство по среде и SSH. Если пользователь просит только диагностику, применяй его в режиме чтения. Если нужен скрипт или изменение, заверши его фактической проверкой либо укажи, какой доступ или стенд требуется для подтверждения.

Обычные задачи выполняй в текущем чате. Перед запуском или повторным использованием подагента проверь [выбор модели](references/models.md). При сложной архитектурной развилке, неясной причине сбоя между компонентами или рискованном изменении данных примени его к конкретному этапу.

В задачах с конкретным проектом [память Talon](references/project-memory.md) включена по умолчанию. Проверь `.agents/talon/learned.md` и резервный `.talon/learned.md` в корне проекта, загрузи только записи по задаче. После подтверждённого результата сохрани полезный способ решения или проверки для следующего чата. Соблюдай ограничения плана и аудита, а также явное отключение памяти.

Когда задача затрагивает Hermes Agent, OpenCode, OpenClaw, Pi или DeepSeek Harness либо конкретную возможность их рантайма, выбери [навык рантайма](references/harness-routing.md) для этого этапа. В остальных задачах используй режим проекта.

Во время работы сопоставляй следующий этап с уже доступными навыками. При конкретном пробеле, например миграции незнакомого фреймворка или диагностике нестандартного тестового раннера, сам открой [Autoskills](../autoskills/SKILL.md) и выполни один целевой `suggest`. Если найден подходящий навык и пользователь разрешил подключение, используй `prepare` в приватном кэше и примени нужную часть инструкции к текущему этапу. При достаточном покрытии продолжай текущим набором. Повторно используй результат подбора, пока задача и стек прежние.

Для оценки самого навыка или плагина Codex открой [Plugin Eval](../qa/references/plugin-eval.md).

При передаче на следующий этап используй текущий результат, критерий приёмки и ссылки на нужный diff или отчёт. Для длинного прогона, повторных ошибок инструмента или запроса на расход токенов открой [управление контекстом](references/context.md). Практики ECC включены в Build, QA, Launch и диагностику Talon.

Если пользователь вызвал навык без задачи, попроси описать желаемый результат. Запросы вне перечисленных режимов обрабатывай обычным способом.
