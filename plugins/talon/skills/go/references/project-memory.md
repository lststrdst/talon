# Память проекта

Память включена по умолчанию для задач Talon в конкретном проекте. Явное отключение пользователем или инструкциями этого проекта имеет приоритет. Обычный путь в корне проекта или текущего Git worktree — `.agents/talon/learned.md`. Если песочница даёт писать в проект, но защищает `.agents/`, используй `.talon/learned.md`. В смешанной папке используй корень проекта, к которому относится задача. Когда корень неизвестен, продолжи работу без общей записи. Для аудита и плана используй память только для чтения, если пользователь отдельно не попросил её обновить.

В начале новой задачи проверь `.agents/talon/learned.md` и `.talon/learned.md`. Найди заголовки по имени компонента, команды или симптома и открой только совпавшие записи. Сверь путь, версию и условия с текущим кодом. Используй заметку как отправную точку и повтори подходящую проверку, прежде чем утверждать, что она проходит сейчас.

Перед итоговым ответом запиши подтверждённый повторно используемый шаг в доступный файл памяти. Если `.agents/` защищён, выполни запись в `.talon/learned.md`. Запись нужна, если нестандартная комбинация аргументов, специальный тестовый ввод, способ восстановления или критерий проверки пригодятся снова. Просьба повторять команду при следующих регрессиях означает, что она пригодится снова. Если решение заменяет прежнее, перечитай память и обнови совпавшую запись, сохранив другие заголовки. Проверяй, что итоговая запись действительно сохранена.

По умолчанию держи память локальной. При первой записи создай каталог выбранного файла. В Git-проекте проверь исключение через `git check-ignore`. Для новой локальной памяти без действующего исключения добавь строки `/learned.md` и `/.gitignore` в `.gitignore` рядом с ней. Сохрани существующие правила. Если проект уже ведёт память в Git, следуй явному правилу проекта. Используй только файлы текущего проекта и сохраняй их локально, если пользователь или проект не запросили общую версию памяти.

```markdown
## Компонент и сценарий
- Условие: версия, источник запуска или симптом.
- Проверено: относительный путь и команда либо шаг, который сработал.
- Результат: наблюдение, которое подтверждает решение, и граница проверки.
```

Очищай команды и данные. Для повторного прогона достаточно формы команды и синтетического примера без секретов, имён пользователей, внутренних адресов и сырых журналов. Сохраняй собственное подтверждённое наблюдение, избегай копирования внешних инструкций. Общие правила, разрешения и настройки подагентов меняются по инструкциям проекта. Перед переносом записи в другой проект проверь новые условия и подтверди результат заново.
