# Яндекс 360, YandexADSCIM и Yandex Cloud

## Выбери продукт и источник истины

Яндекс 360 для бизнеса покрывает сотрудников, группы, подразделения, домены, почту и единый вход. Yandex Cloud покрывает облачные ресурсы, внутренние и публичные зоны Cloud DNS и IAM. Для Яндекс Трекера учитывай тип организации и соответствующие права. Перед проверкой сверь конкретный продукт и организацию. [Яндекс 360 API](https://yandex.ru/dev/api360/) · [Трекер](https://yandex.ru/support/tracker/ru/api/about-api) · [Зоны Cloud DNS](https://yandex.cloud/ru/docs/dns/concepts/dns-zone)

## YandexADSCIM и SSO

1. Определи установленную редакцию. Яндекс описывает текущую Docker-версию для AD, ALD Pro/FreeIPA, Samba DC и Red ADM. Для старой службы Windows применяй отдельное руководство и её схему `AD_Users.config`. Для Docker проверь образ, его фактическую версию, `application.json` и конфигурацию монтирования, включая проверку доступности файлов для пользователя контейнера. [Выбор редакции](https://yandex.ru/support/yandex-360/business/admin/ru/sso/scim) · [Docker](https://yandex.ru/support/yandex-360/business/admin/ru/sso/scim/scim-new) · [Служба Windows](https://yandex.ru/support/yandex-360/business/admin/ru/sso/scim/scim-windows/scim-setup)
2. Сверь тип каталога, проверку сертификата LDAPS, учётную запись чтения, базовый DN, фильтры и сопоставление пользователей и групп. Уточни постоянный идентификатор в конфигурации, отображение логина и почты, коллизии, исключённые OU и полноту страниц. Отдельно сверь назначение OAuth-приложения, Domain ID и разрешений SCIM, не выводя их значения в отчёт.
3. Для Docker при настройке сверь `adscim.sync.dryRun: true` в фактически загруженном конфиге. Даже пробный режим читает настроенные каталоги и обращается к сервису, поэтому используй согласованную тестовую область. Зафиксируй ожидаемые количества операций и изменений атрибутов. Отдельно проверь `allowUsersDeletion`, `allowGroupsDeletion` и настройки подразделений. В этой редакции пропуск пользователя в LDAP может означать блокировку в Яндексе. Пустая выборка, ошибки страниц, смена идентификатора или несколько лесов требуют отдельной сверки перед разрешением блокировок и удаления. [Настройка и диагностика Docker-версии](https://yandex.ru/support/yandex-360/business/admin/ru/sso/scim/scim-new)
4. Различай проверку здоровья процесса, чтение источника, план `dryRun`, эффект пилотной синхронизации и повторный прогон. Сверь несколько тестовых объектов по стабильному идентификатору и ожидаемые членства. Для импорта подразделений проверь флаг в конфиге и настройку в кабинете. Для SAML отдельно сверь издателя IdP, ACS и поля из установленного шаблона, сертификат и фактический вход тестового сотрудника. Успешный SSO и актуальность объектов проверяются разными наблюдениями. [Настройка SSO](https://yandex.ru/support/yandex-360/business/admin/ru/sso/setup)

## API и почтовые домены

- Для отчётов по сотрудникам, группам и подразделениям используй Directory API по нужной версии. Сверь базовый хост, область OAuth и правила страниц в документации выбранного метода. Для синхронизации с LDAP проверь, кто владеет полем: запись через API может быть перезаписана очередным прогоном. [Документация доступа](https://yandex.ru/dev/yandex-360/api360/ru/access) · [Directory API v2](https://yandex.ru/dev/api360/doc/ru/directory/)
- Для почты найди авторитетные DNS-серверы зоны. Сверь MX, SPF, DKIM и применяемую политику DMARC, включая работающих отправителей и селектор из кабинета. Сопоставь авторитетный ответ и видимость из внешнего резолвера с учётом TTL. Подтверди результат по тестовой доставке и заголовку `Authentication-Results`, когда такая проверка согласована. [Настройка DNS](https://yandex.ru/support/yandex-360/business/admin/ru/domains/dns/) · [DKIM](https://yandex.ru/support/yandex-360/business/admin/ru/domains/dns/dkim) · [Диагностика почты](https://www.yandex.ru/support/yandex-360/business/admin/ru/mail/troubleshooting)
- Для Cloud DNS определи публичную или внутреннюю зону и сеть клиента. Внутренний ответ проверяй из привязанной VPC или через настроенное входящее DNS-подключение. Для облачных ресурсов сверяй роль, каталог и сервисный аккаунт с документацией IAM для конкретной операции. [Cloud DNS](https://yandex.cloud/ru/docs/dns/concepts/) · [Сервисные аккаунты](https://yandex.cloud/ru/docs/iam/concepts/users/service-accounts)
- Для Трекера начни с формата запросов и доступа выбранной организации. Для Диска и интеграций с файлами выбери поддерживаемый API или WebDAV. В тестах используй выделенную очередь, папку или подмену API в зависимости от задачи. [Трекер API](https://yandex.ru/support/tracker/ru/api/common-format) · [Диск WebDAV](https://yandex.ru/dev/disk/webdav)
