# Экспорт изображения и проверка в интерфейсе

Сначала сверяй соглашения проекта и фактическое место показа. Ширина файла в пикселях определяется шириной слота и нужными плотностями, а бюджет размера — существующим сценарием загрузки. Оставь исходник для повторного экспорта, если он входит в результат. Делай версии из одного источника.

- **Адаптивность.** Если композиция одинакова, используй варианты ширины с `srcset` и `sizes` или штатный компонент изображений. При разной композиции используй отдельный кадр и `picture` либо эквивалент фреймворка. На узком экране проверь положение главного объекта после CSS-кадрирования.
- **Формат.** Для фотографий сравни поддерживаемые проектом WebP, AVIF и JPEG по размеру и видимому качеству. Для прозрачных графических деталей проверь альфа-канал в PNG или WebP. Учитывай ориентацию EXIF до кадрирования. Для критичных цветов проверь профиль и рендер на целевом носителе. Убирай лишние метаданные при публикации, если проекту они не нужны.
- **Доступность.** Для информативного изображения подбери `alt` по его роли на странице, для декоративного `img` используй пустой `alt`. Для изображения-кнопки укажи действие. Смысловой текст и надписи интерфейса держи редактируемыми, когда задача допускает. Для текста поверх фотографии проверь контраст на всех вариантах кадра. [Дерево решений W3C](https://www.w3.org/WAI/tutorials/images/decision-tree/)

## Быстрый экспорт

Примеры для существующего изображения в sRGB и превью шириной до 640 px. Укажи исходный файл и новый путь вывода. Меняй ширину и степень сжатия по нужному слоту и визуальному сравнению.

Если Sharp доступен в зависимостях Node.js, выполни из рабочего каталога проекта. [Sharp](https://github.com/lovell/sharp) · [Параметры изменения размера](https://sharp.pixelplumbing.com/api-resize/)

```sh
node - "$visual_source" "$visual_output" <<'NODE'
const sharp = require('sharp');
const [input, output] = process.argv.slice(2);

async function main() {
  await sharp(input)
    .autoOrient()
    .resize({ width: 640, withoutEnlargement: true })
    .webp({ quality: 82 })
    .toFile(output);
  const { format, width, height, hasAlpha } = await sharp(output).metadata();
  console.log({ format, width, height, hasAlpha });
}

main().catch((error) => {
  console.error(error.message);
  process.exitCode = 1;
});
NODE
```

Для разового преобразования установленным ImageMagick 7 с явным выводом WebP. [ImageMagick](https://github.com/ImageMagick/ImageMagick) · [Порядок операций CLI](https://imagemagick.org/command-line-processing/)

```sh
magick "$visual_source" -auto-orient -resize '640x>' -strip -quality 82 "webp:$visual_output"
magick identify "$visual_output"
```

## Проверь доставку и рендер

Открой исходник и итоговые файлы. Проверь декодирование, ширину, высоту, размер на диске и прозрачность там, где она требуется. Для обрезки сравни края и область фокуса до и после преобразования. Если файл подключён к интерфейсу, открой реальную страницу или существующую историю компонента в Storybook. На узком и широком экранах проверь фактически загруженный источник, видимый кадр, читаемость наложенного текста и стабильность размеров блока при загрузке. Для браузерных инструментов используй [браузерные проверки Talon](../../checks/references/browser.md). [Проверки UI в Storybook](https://storybook.js.org/docs/writing-tests/index)
